# 04. 오운완 인증 시스템

## 설계 원칙: 마찰을 0에 가깝게

인증 시스템의 성패는 딱 하나로 갈린다. **"인증하는 데 몇 번의 동작이 필요한가."**

| 방식 | 필요 동작 | 예상 참여율 |
|---|---|---|
| 사진 찍어서 올리기 | 5~6단계 | 5% 미만 |
| 댓글에 텍스트 쓰기 | 3단계 | 10~20% |
| 투표 선택지 누르기 | 2단계 | 30~50% |
| **인라인 버튼 1탭** | **1단계** | **40~60%** |

"혼자보는 운동" 컨셉에서 사진 인증은 컨셉 위반이자 참여율 자살이다.
**1탭 버튼을 기본으로, 원하는 사람만 더 깊이 들어가는 계단 구조**로 간다.

---

## 3단계 계단 구조

### Level 1 — 인라인 버튼 (모두, 1탭)

채널 메시지에 붙는 `[💪 했다] [😮‍💨 오늘은 못 했다]` 버튼을 누르는 것. 진입 장벽 없음.

**구현: 텔레그램 "리액션"이 아니라 봇이 붙이는 인라인 키보드다.**
`night_checkin()`(jobs.py)이 `reply_markup`으로 버튼을 달아 보내고,
`callback_query`(commands.py `_on_callback`)로 클릭을 받는다.

> **처음엔 채널 이모지 리액션(Reactions 설정)으로 구현했었는데, 아래 기술적 제약 때문에
> 인라인 버튼으로 바꿨다.** 리액션은 채널 설정에서 이모지를 제한해봐야 여전히
> "몇 명이 눌렀는지"만 알 수 있고 "누가" 눌렀는지는 봇에게 안 온다.

**⚠️ 참고 (리액션이 아닌 이유):**
채널 메시지의 **리액션**은 익명 집계로만 온다. 봇 API의 `message_reaction_count` 업데이트는
"💪 87개"라는 총계만 주고 누가 눌렀는지는 알려주지 않는다. 반면 **인라인 버튼의 콜백
(`callback_query`)에는 누른 사람의 user_id 가 그대로 온다** — 그래서 버튼 방식이면
Level 1 한 번의 탭만으로 개인별 스트릭까지 정확히 기록된다. DM(Level 3)으로 갈아탈
필요 없이 채널 안에서 끝난다.

> **😮‍💨 를 반드시 넣을 것.** 못 한 사람에게도 누를 버튼을 줘야 한다. 누를 게 없으면 그냥 채널을 나간다.

**클릭하면 뭐가 보이나 — 팝업으로 주간/월간 진행률.**
`[💪 했다]`를 누르면 `answerCallbackQuery(show_alert=True)`로 뜨는 팝업에
연속/최고 기록과 함께 이번 주·이번 달 진행바가 바로 보인다 (`commands.py`
`_checkin_toast`). 토스트(2~3초 만에 사라짐) 대신 알림창을 쓰는 이유는 순전히
**시인성** 때문 — 눌렀는데 뭘 기록했는지 바로 안 보이면 누른 보람이 없다.

```
💪 오늘 기록 완료

연속     5일 · 최고 12일
이번 주 ▓▓▓▓▓░░ 5/7
이번 달 ▓▓▓▓▓▓░░░░ 18/23
```

**놓친 날도 그 자리에서 채운다 — 캐치업 버튼.**
이번 주 중 기록이 아예 없는 날(최근 3개)이 있으면, 오늘 버튼을 처음 누른 직후
채널에 답장으로 `[💪 7/28(화) 했다]` 같은 버튼이 개인화되어 달려 온다
(`_offer_catchup`). 콜백 데이터 자체가 `checkin:done:2026-07-28`처럼 날짜를
담고 있어서 과거 날짜 캐치업도 `_on_callback` 하나로 똑같이 처리된다.
중복 클릭이나 캐치업 버튼 클릭 자체에는 캐치업 제안을 다시 띄우지 않는다 —
매일 같은 안내가 반복되면 그것도 마찰이다.

### Level 2 — 익명 투표 (원하는 사람, 2탭)

밤 체크인 메시지에 붙이는 투표. 익명이라 부담이 없으면서, 난이도별 분포가 잡힌다.

```
오늘 어디까지 했나요?

🟢 귀찮음 모드
🟡 보통 모드
🔴 여유 모드
😮‍💨 오늘은 패스
```

`sendPoll` 의 `is_anonymous=true` (기본값)로 보내면 결과 집계만 채널에 표시된다.
Level 1과 마찬가지로 개인 추적은 안 되지만, **"어제 68%가 🟢을 골랐습니다"** 같은 다음 날 콘텐츠 소재가 공짜로 나온다.

### Level 3 — 봇 DM 명령 (더 자세히 보고 싶은 사람)

Level 1(채널 인라인 버튼)만으로 개인 스트릭은 이미 정확히 기록된다.
DM은 이제 "기록 수단"이 아니라 **조회·부가 기록 수단**이다.

```
/done   오늘 완료 처리 → 스트릭 +1 (버튼과 동일, DM 에서도 가능)
/streak 내 현재 기록 자세히 보기
/skip   오늘은 패스 (스트릭 유지, 죄책감 제거용)
/random 지금 당장 할 30초 운동 랜덤 추출
/weight 주간 체중 기록 (선택, 본인만 볼 수 있음)
```

📊 기록 자체는 채널 버튼 한 번으로 끝나고, `/streak` 같은 명령은 더 자세히 보고 싶은
사람만 DM 에서 추가로 쓰면 된다.

## 대안: 댓글 그룹 인증 (Level 1.5)

채널에 댓글 그룹을 연결하면, 댓글에 한 줄 쓰는 방식도 가능하다.
**그룹 메시지는 채널과 달리 발신자가 식별되므로, 봇이 개인 스트릭을 계산할 수 있다.**

**포맷을 극단적으로 단순화한다:**
```
오운완 인증은 댓글에 이렇게만:

ㅇㅇ      → 했다
ㅇㅇ 🟢   → 귀찮음 모드로 했다
ㄴㄴ      → 오늘은 못 했다
```

두 글자면 끝난다. 문장을 쓰게 만드는 순간 참여율이 반토막 난다.

**단, 댓글 그룹은 양날의 검이다:**
- 초기 구독자가 적을 때 댓글이 0개면 "죽은 채널"처럼 보인다 → **구독자 100명 넘기 전엔 열지 말 것**
- 스팸·광고 유입에 대한 관리 부담이 생긴다 → 슬로우 모드(30초) + 새 멤버 미디어 제한 권장

## 스트릭 규칙 (죄책감 제거가 목적)

일반적인 스트릭 시스템은 하루 빠지면 0으로 리셋된다. **이 채널에서는 그렇게 하면 안 된다.**
스트릭이 0이 되는 순간 사람들은 채널을 떠난다.

| 규칙 | 내용 | 이유 |
|---|---|---|
| **🟢도 완전한 1일** | 난이도 무관, 완료는 완료 | 가장 중요한 규칙 |
| **주 1회 무료 패스** | `/skip` 사용 시 스트릭 유지 | 아프거나 일이 터지는 날은 반드시 온다 |
| **끊겨도 0 아님** | "최고 기록 18일 / 현재 3일" 병기 | 과거 성취를 지우지 않음 |
| **주간 단위 병행** | "이번 주 4/7일" 도 함께 표시 | 연속 실패해도 주간 지표는 살아있음 |
| **월요일 자동 사면** | 2주에 한 번 전원 리셋 데이 선언 | 이탈자 복귀 창구 |

봇 응답 예시:
```
💪 오운완 기록됨

현재 연속  3일
최고 기록  18일
이번 주    4 / 7일
3kg 프로젝트  D+26 / 84
```

## 인증률을 끌어올리는 실전 장치 5가지

**1. 밤 체크인을 절대 거르지 않는다.**
인증은 요청받아야 일어난다. 아침 미션만 있고 밤에 "했나요?"를 안 물으면 인증률이 절반 이하로 떨어진다.

**2. 마지막 줄을 항상 인증 문구로 고정한다.**
```
────────
하나라도 했으면 💪
```
매일 같은 자리, 같은 문구. 조건반사가 붙는다.

**3. 어제 숫자를 오늘 공개한다.**
```
어제 💪 눌러주신 분 87명.
그중 🟢이 61명이었습니다. 그거면 충분합니다.
```
사회적 증거이면서 동시에 "다들 최소 단계만 하는구나"라는 안도감을 준다. 이 안도감이 이 채널의 핵심 정서다.

**4. 못 한 사람에게도 누를 버튼을 준다.**
😮‍💨 리액션, `/skip` 명령, 투표의 "오늘은 패스" 선택지. 못 한 날에도 채널과 접점이 유지돼야 다음 날 돌아온다.

**5. 마일스톤에만 축하한다.**
매일 축하하면 인플레이션이 온다. 7일 / 21일 / 50일 / 84일(시즌 완주)에만.
```
🎉 7일 연속

일주일 채우셨습니다. 
습관이 만들어지기 시작하는 지점이 딱 여기입니다.
```

## 하지 말 것

- ❌ **사진 인증 요구** — 컨셉 위반이자 참여율 파괴
- ❌ **랭킹 / 리더보드** — "혼자보는" 컨셉과 정면 충돌. 상위권만 남고 하위권이 이탈한다
- ❌ **미인증자 지목** — "○○님 3일째 안 하셨네요" 같은 건 즉시 차단 사유
- ❌ **체중 공개 유도** — 체중은 봇 DM 안에서 본인만 보는 데이터
- ❌ **매일 체중 측정 권장** — 주 1회 원칙 (일요일 아침)

## 봇 구현 시 보안 원칙

**봇 토큰은 절대 코드나 레포에 넣지 않는다.**

- 환경변수 `TELEGRAM_BOT_TOKEN` 으로만 주입
- `.env` 는 `.gitignore` 에 등록 (레포에 이미 반영됨)
- 토큰이 유출되면 즉시 **BotFather → `/revoke`** 로 재발급
- 채널 관리자 권한은 필요한 것만 부여 (메시지 발행 권한만이면 충분)
- 사용자 데이터(스트릭·체중)는 텔레그램 user_id 기준 최소 저장. 체중 기록은 본인 조회만 가능하게.

```python
import os

TOKEN = os.environ["TELEGRAM_BOT_TOKEN"]  # 하드코딩 금지
```
